# FocusBoard  Полноценная Kanban-доска для личных рабочих задач. Проект показывает путь от React-интерфейса к небольшому full-stack приложению: API, SQLite, тесты, доступные элементы управления и production-сборка в Docker.  ## Возможности  - создание, редактирование и удаление задач; - четыре статуса: бэклог, в работе, на проверке и готово; - поиск и фильтрация по приоритету; - перенос задач мышью и через доступный `<select>` — работает с клавиатурой и на телефоне; - сохранение на Fastify API в SQLite; - индикаторы загрузки, ошибок и повторная синхронизация; - тесты API и ключевых UI-сценариев;`n- компактная статистика задач на главном экране и GitHub Pages demo без карты; - единый production-сервер: Fastify раздаёт API и готовую React-сборку.  ## Стек  React, JavaScript, Vite, Fastify, SQLite (`better-sqlite3`), Vitest, Testing Library и Docker.  ## Локальный запуск  ```bash npm install npm run server npm run dev ```  Фронтенд откроется на `http://localhost:5173`, API — на `http://127.0.0.1:3001`.  ## Проверки  ```bash npm test npm run build ```  ## API  | Метод | Маршрут | Назначение | | --- | --- | --- | | GET | `/health` | проверка доступности сервера | | GET | `/api/tasks` | список задач | | POST | `/api/tasks` | создание задачи | | PATCH | `/api/tasks/:id` | редактирование или перенос задачи | | DELETE | `/api/tasks/:id` | удаление задачи |  Данные сохраняются в локальном `server/data/focus-board.db`; файл базы намеренно исключён из Git.  ## Production и Docker  Dockerfile собирает React и запускает один Fastify-сервер: интерфейс открывается на том же адресе, что и API. SQLite хранится в подключённом томе, поэтому данные не пропадают после перезапуска контейнера.  ```bash docker compose up --build ```  После запуска открой `http://localhost:3001`. Для внешнего хостинга назначь публичный HTTPS-домен и передай его в `CORS_ORIGIN`, если фронтенд будет размещён отдельно от API.  ## Деплой на Render  В корне уже лежит `render.yaml`: это Blueprint для Docker-сервиса с проверкой `/health` и автоматическим деплоем из `main`. Он запускает единый Fastify-сервер, поэтому в Render не нужно отдельно настраивать frontend и API.  Для бесплатной демо-версии можно импортировать Blueprint как есть. SQLite-файл при таком варианте хранится на временном диске и может сброситься после перезапуска. Для постоянных пользовательских данных в настройках сервиса подключи Persistent Disk и укажи переменную `DATABASE_FILE=/var/data/focus-board.db` с точкой монтирования `/var/data`.  ## Настройка отдельного фронтенда  Фронтенд берёт адрес API из переменной `VITE_API_URL`. Для отдельного деплоя создай `.env` по примеру `.env.example`, укажи публичный HTTPS-адрес API и выполни `npm run build`. Сам `.env` не публикуется в репозиторий.  ## Что рассказать на собеседовании  В проекте я отделил работу с API в `src/api/tasksApi.js`, бизнес-логику задач вынес в хук `useTasks`, а сервер сделал отдельным Fastify-приложением с SQLite-репозиторием. Данные переживают перезапуск сервера, UI умеет обрабатывать ошибки сети, основные сценарии защищены API- и компонентными тестами, а production-сборка запускается одним Docker-контейнером.
